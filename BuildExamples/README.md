# BuildExamples

Фикстуры для билдера Luwu -> Luau: «как должен выглядеть рабочий Luwu-код после
перевода в рабочий Luau».

Это не эталонный вывод конкретного билдера, а соглашение: исходник на Luwu и
рядом — работающий Luau, который делает то же самое. Luau-сторона не обязана
повторять Luwu один в один, она обязана работать и оставаться читаемой.

## Формат

- Пара файлов с одинаковым базовым именем: `X.luwu` + `X.luau`.
- `X.luwu` — код, который пишет пользователь (по документации Luwu).
- `X.luau` — результат: **чистый Luau 0.730, без типов вообще**.
- Ни одного `require`, ни общих модулей, никакого рантайма: каждый пример
  самодостаточен и запускается как есть.
- Шапка `.luau` — короткий комментарий «что во что переведено».
- Папки: `class/`, `trait/`, `enum/`, `features/`.

Проверка: `luau-analyze X.luau` (должно быть 0 замечаний) и `lune run X.luau`.
`.luwu` требует `seal`/Luwu и здесь не проверяется.

## Общие правила

1. **Типы стираются полностью.** Аннотации, дженерики, `type`-алиасы, union'ы —
   всё это забота Luwu. В Luau не остаётся ничего типового.
2. **`const` переводится один в один.** В Luau 0.730 `const` для локальных
   привязок есть: `const x = 1`, `const function f()`.
3. **Места вызовов не переписываются.** Если в Luwu было `Dog("Oreo", 3)`,
   в Luau остаётся `Dog("Oreo", 3)`.
4. **Luwu-семантика без аналога отбрасывается**, а не эмулируется:
   `private`, `const`-поля, проверка `self`, инварианты класса. Важно поведение,
   инкапсуляция — нет.
5. **`if local` / `if const` в Luau 0.730 отсутствуют** (свежий анализатор их
   понимает, а парсер Luau — нет). Поэтому `if const x = e then` разворачивается
   в обычный `if`, см. `features/expressive-control-flow`.
6. **`<+` / `<-` в Luau отсутствуют** — push/pop переводятся в `table.insert` /
   `table.remove`.
7. **`__len` в Luau есть**, поэтому `#obj` работает нативно, если класс
   определяет `__len`.

## Классы

Класс — обычная таблица, которая служит собственным метатейблом и вызывается
через `__call`. Так сохраняются и `Dog(...)`, и `dog:method()`, и поля.

```luau
const Dog = {}
Dog.__index = Dog

function Dog.new(name, age)
	const self = setmetatable({}, Dog)
	self.name = name
	self.age = age
	return self
end

function Dog:bark()
	print(`{self.name} barked!`)
end

setmetatable(Dog, {
	__call = function(_, ...)
		return Dog.new(...)
	end,
})
```

Правила по видам объявлений:

- **Primary-конструктор** `class Dog(name, age)` -> параметры становятся полями
  в `new`, в порядке объявления.
- **POD-класс** (нет конструктора): `Class()` и `Class { ... }` ведут в один
  `new(init)`. Дефолты полей собираются в функции `*_defaults()`, чтобы каждый
  объект получал свежую таблицу, а `init` лишь накладывается сверху.
- **Вычисляемые поля** (`text = lower(raw)`): сначала параметры, потом
  инициализаторы полей в порядке объявления. Инициализаторы видят параметры.
- **`__init`**: `new(...)` создаёт объект, вызывает `Class.__init(self, ...)`,
  возвращает объект.
- **Статические функции** (без `self`): обычная функция на таблице класса,
  вызов с точкой не меняется.
- **Метаметоды** (`__add`, `__eq`, `__tostring`, ...): кладутся на таблицу
  класса как есть — она и есть метатейбл объекта.
- **`public` / `private` / `const`**: модификаторы отбрасываются. `private`
  поля остаются обычными полями, но не попадают в метаданные класса.
- **Дженерики** `Box<T>` -> просто `Box`, параметры типов исчезают.
- **Библиотека `class`:**
  - `class.isinstance(x, C)` -> `getmetatable(x) == C`;
  - `class.of(x)` -> `getmetatable(x)` (у обычной таблицы — `nil`);
  - `class.name(C)` -> поле `C.__name` (в Luau понятия имени класса нет);
  - `class.fields(x)` -> обычный список `C.fields` из `{ name, isconst, position }`;
  - `class.member(x, name)` -> запись из таблицы `C.members`; объявление
    печатается по её полям.
- **`type(obj)`**: в Luwu `"object"` / `"class"`, в Luau всегда `"table"`;
  объект отличается по `getmetatable(x) ~= nil`.

## Трейты

Трейт — таблица методов по умолчанию. `implements` копирует методы в класс,
если класс не определил свои.

```luau
const Lootable = {}

function Lootable:drop()
	const dropped = self.loot
	self.loot = {}
	return dropped
end

Chest.drop = Lootable.drop
```

- **Общее поведение**: одно определение на трейт, копии в каждом классе.
- **`expect`**: только проверка Luwu, в Luau ничего не эмитится — метод просто
  читает поле.
- **Переопределение**: копия не затирает метод класса; версия трейта остаётся
  доступной как `Trait.method(self)`. Никакого `super`.
- **`needs`**: трейт без методов ничего не эмитит; факт «реализует оба» — только
  проверка Luwu.
- **`final` / статические члены трейта**: `final` значит «не копируется вниз»,
  статическая функция — просто функция на таблице трейта.
- **Трейт с параметрами**: трейт становится функцией-фабрикой, возвращающей
  таблицу `{ значения по умолчанию, методы }`. Методы идут на класс, значения —
  на объект.
- **`__create` / `__implemented`** (трейт-фабрика): `__create` -> обычная
  функция `Component(tag)`, `__implemented` -> вызов `implemented(class)` после
  определения класса, реестр — массив рядом с трейтом.

## Enum

В Luwu нет `enum`. Вариант — это трейт с общим поведением плюс один класс на
значение:

- **singletons**: у класса фиксированные поля-значения, значения создаются
  вызовом `Mercury()`;
- **tagged union**: вариант с данными получает своё поле-тег (`kind`) и `__init`;
- **shared methods**: вся логика в трейте, классы несут только данные.

## Остальные фичи

- **Destructuring** `const .{ name, level } = player` -> одно multiple assignment
  `const name, level = player.name, player.level`. В `for` заголовке — те же
  строки в теле цикла. Работает и для объектов.
- **Restructuring** `.{ name, level }` -> `{ name = name, level = level }`.
- **Bundles** `.(3, 4)` -> массив `{ 3, 4 }` + чтение по индексу. Упрощения:
  нет value-equality/хэширования (ключ-бандл -> строковый ключ) и нет
  неизменяемости.
- **`none`** -> один sentinel-таблиц на всё: `#list` не теряет элемент,
  `x == none` сравнивает с одним значением. Раз таблица truthy, `if x then`
  для возможного `none` превращается в `if x ~= none then`.
- **Table comprehensions** `{ for _, n in xs when c give v }` -> пустой массив,
  `for`, `if` для `when`, `table.insert` для `give`.
- **Expressive control flow**:
  - `x or return v` -> `if x == nil then return v end`;
  - `if const x = e when c` -> `if x ~= nil and c then`;
  - `do ... give v` -> немедленно вызываемая функция с `return v`;
  - `for ... when c` -> цикл с `if c then` в теле.
- **`try`** -> `pcall`; `Ok(value)` / `Err(error)` -> флаг `pcall` и его
  возвращаемые значения.
- **Default arguments** -> `if p == nil then p = default end` в начале функции
  или в начале `new`.
- **`table.drop(t, v)`** -> `table.find` + `if index ~= nil then table.remove(...)
  end`; несколько совпадений — цикл `while`. Просто
  `table.remove(t, table.find(t, v))` без проверки удаляет последний элемент,
  когда значения нет.
